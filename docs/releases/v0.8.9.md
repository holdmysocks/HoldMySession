# HoldMySession 0.8.9

The in-app update now gets past a program that still has the old files open.

- **What went wrong in 0.8.8's update.** The step no longer locked `app.asar` (fixed in 0.8.7), and the archive was moved aside fine. But copying the new `HoldMySession.exe` failed for 20 seconds with `EPIPE, The process cannot access the file because it is being used by another process`: some program was still running from the install folder. The step only went looking for such programs when the error was a lock error, and Windows reported this one as `EPIPE`, so it never looked.
- **Now it looks first, and after any failure.** Before touching a file, and again after any failed move or copy (every couple of seconds), the update step finds each program running from the install folder, ends it, and tries again. `apply-update.log` lists what it found and ended, so if a program is still in the way, the log says which.
- If the files still cannot be replaced, the old version is put back and started again, as before.

**Updating to 0.8.9.** From 0.8.7 or 0.8.8, the update uses this version's own copy of the step, so Update now should work from the app.

Update every linked machine.

Checksums are in `SHA256SUMS.txt`.

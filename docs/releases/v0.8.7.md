# HoldMySession 0.8.7

Updating from the app no longer stops at "resource busy or locked".

- **The update step now clears whatever is holding the program's files.** After Update now, the new version is unpacked and a small step waits for the app to quit and swaps the files. In 0.8.6 it could stop with `EBUSY: resource busy or locked, rename ...app.asar`, because something was still running from the program's folder: a helper that had not exited, or a copy a Claude Code hook had just started. The step now finds any program running from the folder, ends it, and tries again, and it writes down what it found in `%USERPROFILE%\.holdmysession\updates\apply-update.log`. If the files still cannot be replaced, the old version is put back and started again.
- **A fix in the update step reaches the update that installs it.** The step now runs the copy that comes with the new version, instead of the copy from the version being replaced.

**Updating to 0.8.7.** From 0.8.6 the update still runs 0.8.6's version of the step, which can fail the same way. Try this first: switch off the two hooks in Settings, Claude Code, close any open Claude Code sessions, check Task Manager shows no other HoldMySession, then press Update now. If it still fails, unzip by hand: quit the app, move the old folder aside and unzip the new one in its place. From 0.8.7 on, the fix applies.

Update every linked machine.

Checksums are in `SHA256SUMS.txt`.

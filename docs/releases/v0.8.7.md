# HoldMySession 0.8.7

Updating from the app no longer stops at "resource busy or locked".

- **The cause was the update step itself.** After Update now, the new version is unpacked and a small step waits for the app to quit and swaps the files, running in Electron's Node mode. In that mode, merely looking at a file called `app.asar` opens it as an archive and keeps it open, and Windows will not rename a file that is open. So the step locked the very file it was about to move, and failed with `EBUSY: resource busy or locked, rename ...app.asar` every time. It now handles `app.asar` as a plain file (`original-fs`), and I checked on a packaged build that no handle is held when the rename happens.
- **If something else does hold the program's files**, such as a helper that has not exited or a copy a Claude Code hook just started, the step now ends any program running from the install folder and tries again, and it writes down what it found in `%USERPROFILE%\.holdmysession\updates\apply-update.log`. If the files still cannot be replaced, the old version is put back and started again.
- **A fix in the update step reaches the update that installs it.** The step runs the copy that comes with the new version, instead of the copy from the version being replaced.

**Updating to 0.8.7.** From 0.8.6 the update still runs 0.8.6's version of the step, which has the lock bug, so update by hand once: quit the app (tray, Quit), move the old folder aside and unzip the new one in its place. From 0.8.7 on, updates from the app work. 0.8.8 is the same code, published so you can try that update.

Update every linked machine.
